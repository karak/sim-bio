# 層の向きと大きさを柵で守り、年代記の型の置き場と受け入れた危険を決める

レビュー (2026-10-10) の R1・R2・R4 の決め。R1・R2 は M27-01〜05 で実装した。R4 は受け入れた危険を書き残すだけで、作りは変えない。

## 背景と問題

- 設計書 2026-09-19 §4 は「依存の向きは一方向」「main.ts は配線のみ」と書くが、M19〜M26 で周辺 (harbor・persist・chronicle・app・ui) に循環が 4 組でき、main.ts は 623 行になっていた。文書は守らせる力を持たない。
- `Chronicle` の型が `src/harbor/` にあり、年代記の意味 (記録・再生の単位) が港の wire の都合に置かれていた。
- 港の confirm・outcomes に人間確認が無いこと、logs が日次予算だけで守られていること、同一オリジンの門が認証でないことは、設計書 09-26 の決めだが「受け入れた危険」としては書かれていない。
- 版が 3 つ並ぶ (`SaveData.version`・`SIM_VERSION`・`RUNNER_STATE_VERSION`) が、関係を 1 か所に書いた文書が無い。

## 決定

1. **層の向きは表 1 つで守る。** `layering.config.mjs` の `ALLOWED` (層 → 読んでよい層。表に無い層は読めない) と `ENTRY` (入口の名指し)・`PACKAGES` (層ごとに読んでよい外部パッケージ) を、eslint の `no-restricted-imports` (静的な import、編集中と CI で落ちる。禁止の形 `FORBIDDEN` は `ALLOWED` の裏返しとして導く) と `tests/unit/architecture.test.ts` (動的 import・深い相対パス・循環・知らない層) の両方が読む。表を変えるのは設計の変更なので、票と一緒に変える。(当初は禁止の表 `FORBIDDEN` だった。M27-05 段 6 で許可の表に裏返した、2026-10-11)
2. **大きさはラチェット。** 既定はファイル 700 行・関数 150 行。超えているものは試験の表に今の値で名指しし、減らしたら表を下げる。増やす方向には書き換えない。`main.ts` は 261 行・`boot` は 218 行 (M27-05 の後の値)。`observe/view.ts` (1074 行・`createObservationView` 836 行) は M27-04 で既定へ戻した (165 行。表から外れた)。
3. **年代記の型は `src/chronicle/chronicle.ts`。** harbor は chronicle を読み、逆は無い。港のクライアントの置き場は port (`src/harbor/store.ts`) で、persist がそれを実装する。
4. **受け入れた危険 (作りは変えない)。** (a) confirm・outcomes は人間確認なし。回避率は順位にしないので汚す動機が薄く、送り手ごとの回数制限と日次予算で量を抑える。(b) `/logs` は回数制限なし・日次予算だけ (fail-open。本体を止めないことを優先、09-26 §6.1)。(c) 同一オリジンの門は CSRF の守りで認証ではない。身元は作らない (B1・Q6)。見直す条件: 回避率を順位や報酬に使うとき、ログの日次予算が毎日尽きるとき。
5. **版 3 つの関係。** `SaveData.version` は島の保存の形 (restore が欠けた場を seed から埋める)。`SIM_VERSION` は本体の規則の版で、年代記の結末の同一性の単位 (golden replay が上げ忘れを落とす)。`RUNNER_STATE_VERSION` は石板の runner の状態の形。係数・規則・刻みを変えたら `SIM_VERSION`、保存の形を変えたらそれぞれの version を上げる。3 つは独立に上がる。

## 検討した案

| | 採った: 表 1 つ + eslint + 試験 | eslint-plugin-import の no-cycle | dependency-cruiser |
|---|---|---|---|
| 依存を増やす | 増やさない (typescript の AST を使う) | 1 つ | 1 つ + 設定ファイル |
| 動的 import・深いパス | 試験が見る | 見る | 見る |
| 大きさのラチェット | 試験 | 無い | 無い |
| 表の置き場 | 1 つ | eslint だけ | 設定だけ |

依存を増やさない今の流儀 (設計書 09-26 §3.1) に合わせ、表を 1 つに置ける案を採った。

## 結果

- 良い: 柵を入れた直後に赤 (循環 19 本・lint 10 件) を見てから直せた。禁じた import を置くと落ちることを 4 通りで確かめた (M27-01 の作業ログ)。
- 悪い: 表の変更が設計の変更になるので、新しい層を足すときは表と票を一緒に書く手間が増える。ラチェットの表も同じ。
- 残り: 票は無い (M27-01〜05 取り込み済み、19d86b3)。置き場の変わった古いコメントの候補は M27-02・03・05 の票の作業ログにあり、承認制。
