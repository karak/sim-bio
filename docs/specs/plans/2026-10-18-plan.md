# 2026-10-18 の計画 (仕上げの残りと、石板へ戻る前の決め)

2026-09-23 のロードマップ (§8 で完了の判定) が残した票を、1 票 1 節の点検表にした。
対象は遊ぶ人 (タイトルから入れる、観察画面で 10 分見ていられる、迎撃の塔の後半に悩める) と、次にこのコードを持つ人 (通し実行が管理下、D1 の予算が測れる)。
この計画が守る決まりは 3 つ。1 票は 1 つの変化で、自分の証拠を持つ。証拠は verify-biotope の層 (A 機械・B LLM・C 人) を名指す。既存の文・コメント・正本の書き換えは審査台で承認を得てからにする。
票の順は M26-20 → M19-03 → M24-02 → M24-03 → M22-09 → M21-11 → M21-03 → M26-14。M19-19 はユーザーの手元の確認を待つ。M11〜M18 の 47 票は、この計画の最後の決めで扱う。

## How to read this

One box is one unit of work. Every box names the evidence that checks it. A nested box is a sub-step of the box above it. Check a box only when its evidence exists, a file, a log line, a screenshot, a test run, or a SHA. The body is a how-to. The appendices explain and record.

進め方はこのプロジェクトの流儀 (auto-memory「M19 を自律で進める」) で、pstack の `playbooks/autopilot-stack.md` に最も近い。1 票ごとに worktree の agent が作り、親 (この chat) が差分を検めて feat/m19 に取り込み、票を done にする。push・PR・merge・配備はユーザーの許可があるときだけ。層 C (審査台・受入の画面・承認) はユーザーの項目で、そこで止まる。

Tests alone are not sufficient verification. A PR is verified only when its unit, live, and perf boxes are all checked.

層の読み方は `.claude/skills/verify-biotope/SKILL.md`。live の箱は、その票の機能の地図 (`features/*.md`) の入口を通し、証拠を `.claude/verify/<日時>-<票>/` に置く。pstack の雲の VM と 10 車線は使わない (Appendix C)。

### Arm the program

- [ ] この計画をユーザーに示し、止まる。進めるのはユーザーの「go」の後。

  - [ ] `grep -l "^status: todo" issues/*.md` で開いている票を数え直す。

### Spawn owners

- [ ] 票ごとに 1 つの agent を `isolation: "worktree"` で出す。brief は票の節の全文、verify-biotope の層、守ること (試験の改名をしない・題を変えない・scenarios.jsonl を触らない・既存の文を書き換えない・push しない)。

- [ ] 同時に動かす agent は 2〜3 まで。定型は sonnet、判断・造形は opus、原因の分からない不具合は fable。

### PR mechanics

- [ ] 取り込みの前に `git diff --stat -- docs/acceptance` を見る。正本の変更は承認の無い限り取り込まない。
- [ ] 取り込みは feat/m19 への merge。票の evidence に commit SHA と試験名を書き、status を done にする。
- [ ] 取り込んだ agent の worktree と枝は、merge-base と未コミット無しを確かめて消す。

### Verdict and merge

- [ ] 票の unit・live・perf の箱がすべて埋まったときだけ done にする。層 C の箱はユーザーが押すまで空のまま。
- [ ] push はユーザーの許可を得てから。1 回の許可は 1 回の push。

### Boot recipe
