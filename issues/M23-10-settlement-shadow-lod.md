# 集落の部品の影と遠距離版の軽量化

## What to build

集落の建物の磨き上げ(settle1、12ddb43)で石を格子の丸めた箱にし、苔・汚れ・目地を足した結果、次のように増えた。
- 近い形の三角形: 小屋 10,178 → 27,142、船台 1,982 → 17,902、石垣 948 → 5,002
- 集落の画: 31.7 → 44.2 万三角形。予算 150 万の内だが、増えた分の多くは影
- 小屋以外の部品は近い形で影を落とすので、海岸の画では集落の部品の影が 13.3 → 42.8 千三角形になった
- settlement.glb: 1.43 → 4.42 MB

ユーザーの指示(2026-09-26 12:28、原文):「影やLODといった軽量化をタスクに積むこと」

やること:
- 小屋以外の部品(灯り柱・立石・船台・石垣・L 字の石垣・衝立)の影を、遠距離版か影専用の形で落とす(小屋と同じ `shadowOnly` の仕組み、M23-04・M23-09)。
- 近い形を切り替える距離と、中間の段が要るかを見直す。
- glb の大きさを減らす(頂点色の精度、共有できる形のインスタンス化など)。

### 2026-09-29

- 基点は feat/m19 の 702a38b(settle1 12ddb43 と L 字の石垣の苔 90b2031 を含む)。実装は ac289ca。
- 影(`src/observe/view.ts`・`src/observe/settlementLayout.ts` の `shadowNodeOf`): 小屋でない部品(灯り柱・立石・船台・石垣・L 字の石垣・衝立)は、近い・遠いに依らず全部の置き場所の影を遠距離版 `<名前>_lod1` で落とす。小屋と同じ `lodProps` の影の形と `shadowOnly` の仕組み(M23-04・M23-09)。本の描画の形と切り替えの距離は変えていない。遠距離版を切った `prop=0` でも同じ形で影を落とす(いつも近い形と比べる画で影が変わらないように)。
  - 近い形の石(settle1 の格子の丸めた箱、歪み 2 cm)で落とさなくてよい理由: 影の地図は 2048 で区域 200 m 四方、1 texel が約 10 cm、`normalBias` 0.6。石の丸めと歪みは影の地図に出ない。
  - 敷石(小屋ごとに 3 枚、252 三角形)は遠距離版が無いので自分の形のまま(9 枚で 2.3 千)。
- glb(`tools/blender/glb_quantize.py`、`observe_settlement.py` の書き出しの後に呼ぶ): 法線を float × 3 → 正規化した int8 × 3(`KHR_mesh_quantization`、byteStride 4)、頂点色を uint16 × 4 → uint8 × 4 に詰める。位置・index・形・三角形・材質は同じ。Blender の書き出しには量子化の設定が無いので、書き出した glb を Python で詰め直す。2 回書き出して同じ .glb(md5 4fe6ac95…)、詰めた glb をもう一度通しても同じ。glTF-Validator(npm `gltf-validator`)errors 0 / warnings 0 / infos 0 / hints 0。
  - **settlement.glb 4,419,896 → 2,941,436 バイト(4.42 → 2.94 MB、−33%)**。内訳は法線 1.48 → 0.49 MB、頂点色 0.99 → 0.49 MB。位置(1.48 MB)と index(0.41 MB)はそのまま。
  - three.js r186 の GLTFLoader は byteStride 4 の int8 を正規化した InterleavedBufferAttribute として読み、`bake.ts` の clone・applyMatrix4・mergeGeometries もそのまま通る(焼いた後の法線は Int8Array の正規化、色は Float32 に作り直す)。
  - 見送った: 位置の量子化(int16 には node の行列で戻す変換が要り、`findNode`・`localOf` がノードの行列を部品の置き場所に使うので影響が広い)。共有できる形のインスタンス化(石はどれも乱数で形が違い、同じ形を並べている所が無い)。
