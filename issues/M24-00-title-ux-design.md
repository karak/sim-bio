# タイトル画面の画面遷移図とワイヤーフレーム (UX の設計)

優先度: Must

## What to build

2026-09-29 08:33 のユーザーの依頼(原文):「新しいタスクを登録。タイトル画面の追加。ロゴとバックグラウンドのデモ。メニューとして新規ゲーム、ロード、コンフィグを出し、シナリオ選択や港への導線を設ける。前提としてUXデザイナー観点として画面遷移図とW/F作成をdocs/uiuxフォルダに作るところから。対象は main 。worktree作業。」

いまの作り (main a89fb3f): 起動するといきなり操作画面(自由モードの島)が開く。石板(シナリオ)は操作画面の中の Tablet から選ぶ。
feat/m19 にはさらに、枠とファイルの読込(src/persist)・港(src/harbor)・訪問の URL(`visit=`)がある。

M24 の実装 (M24-01〜03) はこの票の図と W/F の上に立つ。先に設計を作り、ユーザーの確かめを通す。

作るもの (docs/uiux/ を新しく作る):
- `docs/uiux/README.md`: フォルダの中身と、図・W/F の読み方
- `docs/uiux/2026-09-29-title-flow.md`: 画面遷移図 (Mermaid の stateDiagram)。画面ごとの目的・入口・出口・戻り道
- `docs/uiux/wireframes/*.svg`: 画面ごとの W/F (ロー・フィデリティ。色は灰の濃淡だけ)

## Acceptance criteria

- [ ] 遷移図に、少なくとも次の画面と遷移がある。どの画面からもタイトルへ戻る道がある
  - タイトル (ロゴ・背景のデモ・メニュー)
  - 新規ゲーム → 自由モード / シナリオ選択 (石板) → 操作画面
  - ロード → 枠 (自動の枠を含む) / ファイル → 操作画面 (元の舞台へ)
  - コンフィグ (何を置くかは下の「決めること」)
  - 港 (判定の出た島の一覧・訪問) への導線
- [ ] URL で直に開く場合 (`scenario=`・`visit=`・`player=`・`dev`) にタイトルを経るか飛ばすかを図に書く。いまの E2E と受入の手順 (feat/m19 の docs/acceptance/scenarios.jsonl) を壊さない側を既定にする
- [ ] W/F: タイトル・新規ゲーム (シナリオ選択)・ロード・コンフィグ・港への入口の 5 枚以上。デスクトップと狭い画面 (幅 390) の 2 つの幅
- [ ] UX の根拠を書く: 最初の 1 分で何が分かるか、メニューの並び (ヒックの法則・既定の選択)、背景のデモが読みを邪魔しないか (コントラスト)。スキル ux-psychologist / garrett-ux-analysis を使う
- [ ] 観察画面の世界観 (動物 3 種のムー意匠の参照) にロゴと背景を寄せる方針を書く
- [ ] ユーザーが審査台 (.claude/localreview) で W/F を見て承認する。承認の日時を作業ログに書く

## 決めること (この票で案を出し、ユーザーに問う)

- 背景のデモ: 観察画面 (3D) の島をゆっくり回すか、操作画面の 2D の島をヘッドレスの台本で回すか。重さ (M23 の予算) と読み込みの時間
- コンフィグに置くもの: 音・画質 (影・遠距離版)・言語・操作の速さの既定・見守り手の名前 など
- 「続きから」を新規ゲーム・ロードと別に出すか (自動の枠があるとき)
- 港は判定の後にしか意味を持たない。タイトルから開いたとき何を見せるか
