# URL と手元の状態の対応(M19-17 の設計案)

状態: 承認済み(2026-09-27、ユーザーが §6 の 1〜3 を案のとおり承認)。チケット issues/M19-17-scenario-save-url.md。

受入(2026-09-27、a-scenario-resume 保留)のメモ:「枠に保存だけできて読み込みができない。初期化もできないというのは制限事項に思える。仕様から見直し、保存できるようにしたうえで、URLと内部ゲーム状態管理を一貫性のあるものにする」

## 1. 今の形と、食い違っているところ

| 場面 | 今の動き | 食い違い |
|---|---|---|
| 自由モードで枠 1 に保存 → `?scenario=sinking` で枠 1 を読む | 押せない(`hud.setReplaceable(!scenario)`) | — |
| 石板の途中で枠 1 に保存 | 島(SaveData)だけ書く。runner の状態・年代記は書かない | 読めても石板の続きにならない。だから読込を止めている |
| 石板の途中の枠 1 を、自由モードで読む | 読める。石板の島が自由モードの島になる | 石板の舞台(seed・種・文明の上書き)が自由モードに紛れ込む |
| 石板の「新しい島」 | 押せない | 石板をやり直すには、判定まで回すか、置き場を消すしかない |
| 石板のファイルの読込 | 押せない | ファイルは SaveData だけなので、石板の続きにできない |
| `?scenario=<知らない id>` | 黙って自由モードになる。URL はそのまま | URL と画面の島が違う |
| 石板を選ぶ(石板の一覧) | `location.search` を書き換えて読み直す | 読み直す前に、石板の続きを書き切る約束が無い(visibilitychange に任せている) |

## 2. 決まり(案)

**URL が「どの島を遊ぶか(舞台)」を決め、手元の保存は、同じ舞台のものだけをその画面で読む。** 保存は、どれも自分の舞台を名乗る。

舞台は 3 つ。

| 舞台 | URL | 介入 | 年代記 | 自動の続き |
|---|---|---|---|---|
| 自由モード | `/`(`scenario` なし) | できる | 取らない | 自動の枠 `auto` |
| 石板 `<id>` | `/?scenario=<id>` | できる(力で払う) | 取る(recorder) | 石板ごとの置き場(`scenarios` の key `<id>`、M19-14) |
| 訪問 | `/?scenario=<id>&visit=<chronicleId>` | できない | 取らない | 読まない・書かない(M19-14) |

開発用の `?player=`(M19-16)は舞台を変えない。送り手の名乗りを変えるだけ(M19-16 の設計に従う)。

知らない `scenario` の id は、自由モードとして開き、URL から `scenario` を `history.replaceState` で消す。`persist.url.unknown_scenario`(warn)を 1 行残す。

## 3. 保存の形: 枠とファイルに舞台を載せる

手動の枠とファイルを、次の包みで書く。

```ts
type SlotSave =
  | { stage: 'free'; save: SaveData }
  | { stage: 'scenario'; scenarioId: string; save: SaveData; runner: RunnerState; chronicle: Chronicle };
```

- 石板の枠は、M19-14 の自動の続き(`ScenarioSave`)と同じ 3 つを、同じ tick で書く。読むときの確かめ(版・石板・seed・`runnerStateMismatch`)も M19-14 の `resumeScenario` と同じものを通す
- 古い枠・古いファイル(包みの無い SaveData)は `free` として読む
- 枠の一覧(`SlotSummary`)に `stage` と石板の名前を足す。HUD の枠の一覧は「枠 1 · 沈む欠片 · 32 年」のように出す
- 大きさ: 石板の枠は年代記のぶん増える(命令の数だけ。島の SaveData に比べて小さい)

## 4. 操作ごとの動き

`確` は確かめのダイアログを通す。今の「新しい島」と同じ `window.confirm` で作り、M21-04(やり直しの効かない操作の確かめ)で揃える。

| 操作 | 自由モード | 石板 `<id>` | 訪問 |
|---|---|---|---|
| 枠へ保存 | `free` を書く | `scenario <id>` を書く(判定の後も書ける。判定の出た状態で書く) | 押せない |
| 同じ舞台の枠から読む | 確 → 島を差し替える | 確 → 島・runner・年代記を差し替える。年表・力・石板の年がその時点に戻る | 押せない |
| 違う舞台の枠から読む | 確 →「石板『X』の枠。石板を開いて読む」→ `?scenario=X` へ移り、開いた直後にその枠を読む | 同じ(自由モードの枠なら `/` へ移る) | 押せない |
| ファイルを読む | 枠と同じ(ファイルも包み) | 枠と同じ | 押せない |
| 新しい島 | 確 → Year 0 の島 | 確 →「石板を初めからやり直す」。今の続きを捨て、Year 0・力の初期値・年表なしから。判定の出た島(港へ出せる島、M19-15)は残す | 押せない |
| 石板を選ぶ・自由モードへ | 今の島を書き切ってから移る | 今の続きを書き切ってから移る | 移るだけ |
| 開き直す | `auto` から続き | 置き場から続き。判定の出た石板は初めから(M19-14 のまま) | 港から引き直す |

違う舞台の枠へ移るときは、読む枠の名前を `sessionStorage` に 1 回だけ置いて渡す(`?load=manual-1` を URL に載せると、読み直しや共有で二度読むため)。移った先で読めなければ、その舞台の自動の続きで開き、`persist.slot.load.failed` を残す。

## 5. 予言と矛盾しないこと

「シナリオ中の読込は予言と矛盾するので無効」(main.ts)は、**別の島を石板の途中に差し込むこと** を禁じる規則として残す。石板の枠は、同じ石板・同じ seed の島を、runner の状態と年代記と一緒に戻すので、差し込みにはならない。

- 戻した島の年代記は、seed からその tick までの命令の列のまま。港へ出しても、訪れた人の回し直しで同じ Digest になる(M19-06 の確かめがそのまま効く)
- 巻き戻しはできるようになる(判定の前の枠を読めば、同じ予言をやり直せる)。回避率(M19-11)は年代記ごとに 1 回数えるので、やり直した年代記は別の年代記として数える

## 6. 決めたこと(2026-09-27 承認)

1. **石板の巻き戻しを許すか。** 案は「許す」(カジュアルな箱庭なので、枠を読めば予言をやり直せる)。許さない場合は、石板の枠は「開き直し用の写し」だけにし、判定の前の枠を読むと、年代記に「巻き戻した」印を付けて港の回避率に数えない、などの縛りが要る
2. **違う舞台の枠を読んだとき、その舞台へ移るか。** 案は「移る(確かめのあと)」。移らない場合は「石板『X』の枠。石板を開いてから読む」と出して押せなくするだけになり、作りは小さい
3. **石板の「新しい島」の名前。** 石板の中では「石板を初めから」と出し分ける案

## 7. 確かめ(E2E、承認のあとに書く)

- 石板で枠 1 に保存 → 介入して進める → 枠 1 を読む → 石板の年・力・年表・年代記の命令の数が保存のときに戻る
- 戻した島を判定まで回して港へ出す → 訪れた側の回し直しで「港の記録と同じ結末」
- 自由モードの枠を石板の中で読む → `/` に移り、その島になる。石板の置き場は書き換わらない
- 石板の「石板を初めから」→ Year 0。判定の出た島は港の口に残る
- `?scenario=nope` → 自由モード、URL から `scenario` が消える
- 包みの無い古い枠・ファイルは自由モードの島として読める
