# インスタンスごとの視錐台カリング

## What to build

three.js の InstancedMesh は丸ごとでしか視錐台で落とさないので、区域の全インスタンスを毎フレーム描いている(集落の画で草 512 千のうち画面の中は 105 千)。草と下草は区画に分けた InstancedMesh にするか、見える分だけを毎フレーム(または数フレームおきに)詰め直す。鐘樹・森の木は lodProps の振り分けに視錐台の判定を足す。群れ(VAT)は frustumCulled = false をやめ、見える個体だけ書く。どの方式にするかは draw call と CPU の時間を測って決める。

別の worktree で進め、終わったら feat/m21 へ取り込む(ユーザーの指示「一連の軽量化は worktree を分けて実施」)。

## 作業ログ

### 2026-09-24

- 実装(c503f67)。方式は「見えるインスタンスを前に詰めて count を見える数にする」(案 b)。
  - `src/observe/render/cull.ts`: `ViewCull` は視錐台を角度 0.03 rad・距離 0.75 m 広げて判定し、カメラが「動いた距離 / 0.75 m + 回った角度 / 0.03 rad」で 0.5 を超えるか画角が変わるまでは詰め直さない。`packVisible` は見えるものを前、見えないものを後ろに並べる。`splitCount` は本の描画を見える数、影の描画・光線の当たり判定・境界の球と箱を並べた全部にする。
  - 草(`grass.ts`): 距離の間引きの詰め直しに房ごとの球(風で撓む分 0.2 m を足す)の判定を足した。送り直しは前の n 房分だけ(`addUpdateRange`)。行列・房の色・`aRoot` は同じ番号で一緒に写す。
  - 鐘樹・森の木(`lodProps`): 近い・遠いの振り分け(0.25 秒ごと)はそのままに、組の中のメッシュ(幹・葉・鐘)ごとの球で並べ替える。
  - 下草: `culledProps`(`instanceProps` + 並べ替え)。群れ(VAT): 視錐台の外の個体は書かない。球の半径は焼いた全フレームの頂点から測る(`VatBake.radius`)。`frustumCulled = false` はそのまま(個体ごとに落とし、0 頭なら描画は起きない)。
  - `view.ts`: 群れ・木・下草・草の更新を `direct`(カメラを動かす)の後へ移した。前のままだと寄せ先へ切り替えた最初のコマが前の画の視錐台で描かれる。
- 影: 影のカメラは区域全体(200 m 四方)を覆うので、影の描画は今までどおり全部を描く。`onBeforeShadow` で count を並べた全部にし、`onAfterShadow` で見える数に戻す(three.js の `WebGLShadowMap` は `onBeforeShadow` の直後に count を読んで描く)。影だけの別の InstancedMesh は作らず、draw call は増えない。
- 光線の当たり判定: 自動カメラ(`shotCamera` の blockers)と寄せ先(`lookFrom`)は画面の外の木にも光線を当てるので、`raycast`・`computeBoundingSphere`・`computeBoundingBox` は並べた全部で見る。境界の球は近い・遠いを組み替えたときだけ測り直す。
