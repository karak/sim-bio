## Acceptance criteria

- [x] 遷移図に、少なくとも次の画面と遷移がある。どの画面からもタイトルへ戻る道がある
  - タイトル (ロゴ・背景のデモ・メニュー)
  - 新規ゲーム → 自由モード / シナリオ選択 (石板) → 操作画面
  - ロード → 枠 (自動の枠を含む) / ファイル → 操作画面 (元の舞台へ)
  - コンフィグ (何を置くかは下の「決めること」)
  - 港 (判定の出た島の一覧・訪問) への導線
- [x] URL で直に開く場合 (`scenario=`・`visit=`・`player=`・`dev`) にタイトルを経るか飛ばすかを図に書く。いまの E2E と受入の手順 (feat/m19 の docs/acceptance/scenarios.jsonl) を壊さない側を既定にする
- [x] W/F: タイトル・新規ゲーム (シナリオ選択)・ロード・コンフィグ・港への入口の 5 枚以上。デスクトップと狭い画面 (幅 390) の 2 つの幅
- [x] UX の根拠を書く: 最初の 1 分で何が分かるか、メニューの並び (ヒックの法則・既定の選択)、背景のデモが読みを邪魔しないか (コントラスト)。スキル ux-psychologist / garrett-ux-analysis を使う
- [x] 観察画面の世界観 (動物 3 種のムー意匠の参照) にロゴと背景を寄せる方針を書く
- [x] ユーザーが審査台 (.claude/localreview) で W/F を見て承認する。承認の日時を作業ログに書く

## 決めること (この票で案を出し、ユーザーに問う)

- 背景のデモ: 観察画面 (3D) の島をゆっくり回すか、操作画面の 2D の島をヘッドレスの台本で回すか。重さ (M23 の予算) と読み込みの時間
- コンフィグに置くもの: 音・画質 (影・遠距離版)・言語・操作の速さの既定・見守り手の名前 など
- 「続きから」を新規ゲーム・ロードと別に出すか (自動の枠があるとき)
- 港は判定の後にしか意味を持たない。タイトルから開いたとき何を見せるか
