# M6 実装計画: 「沈む欠片」をジレンマのあるゲームとして遊べるようにする

**Goal:** シナリオ 1 本(沈む欠片)を、プレイヤーが「限られた力をどこに使うか」で悩みながら遊べる状態にする。

**設計書:** `docs/specs/2026-09-19-ecosystem-sim-design.md`(§4.10 シナリオ層、§4.11 生気層)
**世界観:** `docs/design/2026-09-19-scenarios-and-world.md`(§1.2 遺産、§4 面白さの根拠、§5 逆算表の 1〜3 が済)

---

## 1. 「ジレンマのある状態で遊べる」の定義

次の 5 つを満たしたら M6 完了とする。すべて証跡(テスト名・SHA・プレイ記録)を付ける。

| # | 条件 | 検証方法 |
|---|---|---|
| G1 | 放置すると滅びる | `tests/slow` 放置 → dead |
| G2 | **単独の素朴戦略では滅びる**: 雨だけ、放流だけ、災害だけ | `tests/slow` 3 戦略 → dead |
| G3 | 力の配分を伴う戦略なら回避できる(正解は 1 つでない) | `tests/slow` 2 通り以上の台本 → alive |
| G4 | 判断材料が画面で読める: 残りの力、種ごとの住める場所、危険の警告、予言の節目 | E2E + 手動プレイ |
| G5 | 手動で 3 回遊び、少なくとも 1 回は負け、負けた理由が石板で分かる | プレイ記録(`docs/specs/plans/2026-09-19-m6-playtest.md`) |

## 2. 現状とギャップ(2026-09-19 計測)

`/tmp/play.mts sinking script` で戦略を 1 つずつ外して 100 年回した結果(size 64、seed 42):

| 戦略 | 結果 | 意味 |
|---|---|---|
| 雨 1.5 倍 + 鹿の放流 + 狼の疫病(現行の台本) | alive | 想定解 |
| 疫病なし | alive | 疫病は不要 |
| **雨だけ** | alive | 雨スライダー 1 回で勝てる |
| **放流だけ** | alive | 5 年ごとの放流だけで勝てる |

つまり今の「沈む欠片」は **介入が無限で無料** なので、どれか 1 つを機械的にやれば勝てる。ジレンマは「選べない」ことから生まれるので、まず希少性が要る。

### サブ要素ごとのギャップ

| サブ要素 | ゲームに必要な理由 | 現状 | ギャップ | チケット |
|---|---|---|---|---|
| **A. 希少性(力の予算)** | 選べないから悩む。雨を続けるか、放流に取っておくか | 介入は無限・無料。`ScenarioRunner.intervene` が回数を数えるだけ | 予算・コスト・収入・維持費がない | M6-01 |
| **B. トレードオフの本体側の根拠** | 「雨は鹿を助けるが狼を谷で殺す」「高地の鹿は森を食う」が本当に起きること | 豊かさの罠(雨 1.9 で狼絶滅)、放牧遅れ、生気は実装済み。沈降で高地だけ残る | 予算下でも成立するか未校正。雨の維持費と収入の比で決まる | M6-04 |
| **C. 読める情報** | 悩むには「どこに放てば生きるか」「あと何年か」「何が危ないか」が見える必要 | 合計グラフ、セル詳細、レイヤー(地形/気温/水分/植生/生気/種の密度)、残り年数 | 種ごとの **住める場所**(適合度)が見えない。力の残量がない。危険の **警告** がない。予言の **節目** が見えない | M6-02, M6-03 |
| **D. 時間の圧力** | 迫ってくるのが見える | 沈降は毎年、地形レイヤーで海が広がる。残り年数表示あり | 陸地率の推移と「半分になる年」の提示がない(M6-03 の節目で足す) | M6-03 |
| **E. 結果と再挑戦** | 負けた理由が分かって次に活かせる | 勝敗オーバーレイ、理由、もう一度 | 理由が「絶滅: deer」だけ。介入回数・使った力・陸地率の内訳がない | M6-03 |
| **F. 校正と証跡** | 「悩める」ことを固定する | 放置 → dead、台本 → alive の 2 ケース | 素朴戦略が負けるケース、別解が勝つケースがない | M6-04 |
| **G. 手動受入** | 数値では「悩ましさ」は測れない | 未実施 | プレイ記録がない | M6-05 |

やらないこと(M7 以降): 文明・信仰・気象塔・空の舟(逆算表 4〜6)。これらは「悩み」を深くするが、1 本を遊べるようにするには A〜G で足りる。

## 3. 設計

### 3.1 星の力(介入の予算)— M6-01

世界観 §1.2 の「輝石は回避手段の燃料」を、見守り手側の資源 **星の力** として実装する。層ではなくシナリオ層の数値。

- `ScenarioDef.budget?`:
  ```ts
  budget?: {
    start: number;                 // 開始時の力
    incomePerYear: number;         // 年収の上限。実際は × 陸地率 × 生気の平均(島が痩せると減る)
    costs: { spawn: number; disaster: number; climate: number }; // コマンド 1 回の値段
    upkeepPerYear: { rainScale: number; tempOffset: number };    // |rainScale−1|·k、|tempOffset|·k を毎年引く
    max?: number;                  // 貯められる上限(省略時 start × 3)
  }
  ```
- `ScenarioRunner`:
  - `power()` を公開。`intervene(cmd)` は値段を引き、足りなければ `{ ok: false, reason: 'budget' }` を返して world に流さない(ログ `cmd.rejected` は main が書く)。
  - 年が変わるたびに `power += incomePerYear × landRatio × vitalityMean − upkeep`。`power < 0` なら 0 にして **気候を既定に戻す**(`set_climate {rainScale:1, tempOffset:0}` を dispatch、ログ `scenario.power.exhausted`)。これが「雨を続けるか」のジレンマの芯。
  - `budget` が無いシナリオは今までどおり無料(既存 4 本は変えない)。
- `spawn_species` に `radius?: number` を足し、main.ts の 3×3 ループを 1 コマンドにする(値段を 1 回で引くため。既存の 1 セル放流はそのまま)。
- 石板に「力 ▮▮▮▮▯ 23 / 60(+8/年、雨の維持 −5/年)」。HUD の放流・災害チップは足りないとき `disabled` 風に見せる(押せるが弾かれて石板が揺れる)。

### 3.2 住みやすさレイヤー — M6-02

`LayerKind` に `` `suit:${id}` `` を足す。色は `suitability(def, temperature, moisture)` を 0(暗)→ 1(その種の色)で塗る。海は今までどおり。レイヤー列の種チップを「密度 / 住みやすさ」の 2 段にする。`references/games/stage-design-ideas.md` §C の「適合度を色で見せる」。これで「高地は寒くて鹿が住めない → 雨を降らせると帯が上がる」が見える。

### 3.3 石板の警告・節目・結果の内訳 — M6-03

- 純粋関数 `scenarioWarnings(def, snapshot, start, power)` → `Warning[]`。種類: `species_low`(基準の 25% 未満)、`land_low`(陸地が基準の 50% 未満)、`power_low`(どのコマンドも買えない)、`upkeep_over_income`(維持費が収入を超えている)。年に 1 回評価し、石板に最大 3 行、ログ `scenario.warning` を種類ごとに初回だけ。
- 節目: `ScenarioDef.milestones?: { atYear: number; text: string }[]`。石板の年表に「50 年目: 陸は半分になる」を先に見せ、到達したら消す。
- 結果の内訳: `Verdict` に `stats?: { interventions: number; powerSpent: number; landRatio: number; totals: Record<string, number> }`。オーバーレイに 3 行で出す。

### 3.4 「沈む欠片」の再設計と校正 — M6-04

- 予言を書き直し、ジレンマを **明示** する: 「雨は高地を鹿の地にするが、雨を降らせ続けるには星の力が要る。力は島が痩せるほど細る。狼を減らす疫病にも力が要る」。
- 予算の初期値(校正で決める。当たり): `start 40, incomePerYear 8, costs {spawn 4, disaster 12, climate 2}, upkeepPerYear {rainScale 20, tempOffset 4}`。雨 1.5 倍の維持費 10/年 > 収入 8 → 続けられない。雨 1.25 倍なら 5/年で放流の余地が残る。
- 校正の判定行列(`tests/slow`):

  | 台本 | 期待 |
  |---|---|
  | 放置 | dead |
  | 雨 1.5 倍を 30 年目から入れっぱなし | dead(力が尽きて雨が止まり、鹿が高地で凍える) |
  | 5 年ごとに鹿を放流し続ける(雨なし) | dead(力が尽きる、または高地に草がなく飢える) |
  | 狼に疫病を打ち続ける | dead |
  | 雨 1.25 倍 + 節約した力で 20 年ごとに鹿を放流 | alive(想定解 1) |
  | 雨なし。力を貯めて 70 年目以降に高地へ集中放流 + 狼が増えたら疫病 | alive(想定解 2) |

  期待どおりにならなければ、予算の数値と `SEA_LEVEL` 沈降量、高地の気温(`LAPSE`)を動かす。**本体の種のパラメータ(species.json)は動かさない**(振動と他シナリオを壊すため)。

### 3.5 手動受入 — M6-05

`docs/specs/plans/2026-09-19-m6-playtest.md` にチェックリストを置き、ブラウザで 3 回遊ぶ。各回に「取った戦略、力の使い方、結果、石板の理由、悩んだ点、分かりにくかった点」を記録する。分かりにくさは M6 内で直す(文言・表示)。数値バランスの再校正は M6-04 に戻す。

### 3.6 校正で分かったこと(2026-09-19、M6-04)

- 予算だけでは「放流だけ」が勝つ: 判定が「>0 なら生存」なので、最後の瞬間の放流や 5 年ごとの延命で通る。判定を **直近 10 年の平均**(`species_mean`)にして、群れとして残っているかを見る。
- 「最後の N 年連続で alive」は捨てた: 高地の群れは年ごとに 5〜31 と振れる(捕食の振動)ので、必ずどこかの谷で途切れる。
- 沈降 0.002(陸 3%)では雨があっても鹿が残らない。0.0015(陸 6%)で「雨あり 7〜19、雨なし 4 前後」の差が出る。
- 雨 1.5 倍は力が尽きて必ず止まる。1.25〜1.4 倍が現実的で、いつ始めるか(早く始めて長く、貯めて遅く始める)で 2 通りの解になる。
- 実測の数値は設計書 §4.12 の表。

## 5. リスク

- **予算を入れても単独戦略が勝つ**: 収入と維持費の比で決まるので、まず「雨 1.5 入れっぱなし → dead」を最初に固定してから他を校正する。それでも勝つなら沈降量を上げる(陸 3% → 2%)。
- **勝てなくなる**: 想定解 2 通りが両方 dead なら予算を緩める。「悩める」より「勝てる」を優先する。
- **通し実行が長い**: 判定行列で 6 ケース × 100 年 × size 64 ≈ 6 分追加。`npm run test:slow` は CI 外のままにする。
- **予算が UI を複雑にする**: 石板 1 行 + チップの見た目だけに留める。ゲージは M6-05 の記録で必要と出たら足す。
