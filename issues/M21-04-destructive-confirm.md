# やり直しの効かない操作は確認のダイアログを経る

優先度: Should

## What to build

受入試験(2026-09-27、a-free-resume)のユーザーのメモ原文(登録の依頼):「「新しい島」「枠から読み込み」その他、やり直しの効かない破壊的変更は確認ダイアログを経由すること」

「新しい島」は M19-05 で確認を付けた。ほかの、今の島を失う操作(枠から読込・ファイルの読込・災害? など)を洗い出し、やり直しが効かないものはすべて同じ確認のダイアログを経るようにする。

追加(2026-09-27、ユーザーの判断で M19-17 からこのチケットへ): 判定の板(`#verdict`)が画面全体を覆うので、判定の後に「枠へ保存」を押す手段が画面に無い(コードは判定の後の保存を受け付ける)。確認のダイアログを揃えるときに、判定の後にも枠へ保存できる道を作る。M19-17 の `window.confirm` もここで揃える。

- ユーザーの判断を仰ぎたい所(安全側に倒して確かめを付けた): 書いてある枠への上書き、判定の出た島を離れる 4 つ(もう一度・自由モードへ・石板を選ぶ・訪れる)。「もう一度」はその名のとおりの操作なので、確かめが煩わしければ外せる(askOf の 1 行)
- ダイアログ: src/ui/confirm.ts。role="alertdialog"・aria-modal、見出しと文を aria-labelledby / aria-describedby で結ぶ。開くと「やめる」に focus(押し間違いの Enter で捨てない)。Esc・背景の押下・「やめる」の Enter は取り消し。Tab は 2 つの札の間を回る。Esc は capture で受けて観察画面の Esc へ渡さない。閉じたら押した札へ focus を返す。z-index 70(人の確かめ 60 より上)
- 石板の選び(`#tablet-select`)は選んだ直後に今の舞台の表示へ戻す。取り消したときに、選んだ石板の名前が残って舞台が変わったように見えないため。移るときはページを開き直す
- 訪れる札(一覧のカードと出港の後のリンク)は、ふつうの押下だけ guard.leave を経る。修飾キー・中の釦(新しいタブ)は今の島を離れないのでそのまま
- 判定の後の枠へ保存: M19-15 で判定の板の外側が pointer-events: none になり、板は真ん中の箱だけなので、HUD の下の行の「枠へ保存」は 1280×720 で覆われていない(E2E で確かめた)。低い窓で板が下の行に重なるときは、板を取っ手で動かす(M19-15)。判定の板に別の保存の札は足していない
- src/ui/clicks.ts は変えていない。確かめは命令(Command)を変えず、通し実行の台本は新しい島・読込・枠へ保存・舞台の移りを使わない
- 古くなったが消していない記述: docs/design/2026-09-27-scenario-save-url.md §4「`確` は確かめのダイアログを通す。今の「新しい島」と同じ `window.confirm` で作り、M21-04(やり直しの効かない操作の確かめ)で揃える。」(window.confirm はもう使わない)。src/ui/Hud.ts の「// 自動の枠をその場で上書きするので、押し間違いで島を失わないよう確かめる」は、確かめる所が main.ts へ移った(すぐ下に「(M21-04 で変更: …)」を足した)
- 確かめた数(2026-09-28、fe5e8ee の上): pnpm run check は vitest 110 files・1046 tests、worker 66 tests、scripts 42 tests。E2E は 1 worker で confirm 6・persist 6・scenarioSave 8・verdict 2・devtools 3 の 25 件と、harbor・smoke・observe・observeEntry・chronicle・logsink の 51 件、計 76 件すべて通る。tests/slow は確かめが命令と台本に関わらないので回していない。check の 1 回目は E2E と並べて回したとき worker のテストが 2 つの unhandled error で落ち、単独で回し直すと 66 件通った(負荷による揺れと見ている)
